# Good Afternoon. 개발 로드맵

갱신일: 2026-09-09. 현재 장르는 짧은 턴제 장사 웹 게임이며, 첫 구현은 「오후의 작은 가게 — 주말 장터」입니다.

## 승인된 구현 기준선

2026-09-09 사용자가 현재 게임과 진행 설계를 승인하셨습니다. 아래 기준선을 유지하며 플레이 관찰과 숙련 확장을 이어갑니다.

- `src/market-game/`의 다섯 영업: 준비 → 판매 → 정산 → 다음 날 → 최종 기록
- 첫날 물량만 선택하고 둘째 날부터 가격 선택
- 더위·비·재료비·축제로 달라지는 조건과 구매·거절·품절 반응
- 매출, 준비 지출, 현금 변화, 이익, 보관과 폐기되는 음료의 연결
- 셋째·넷째 날 하루 보관함 선택, 다음 날 재료비·손님 단서, 보관분의 우선 판매
- 보관분의 재료값을 이월하는 손익 계산, 기존 v1 저장 기록 호환
- 같은 날 재시도, 자동 저장, 기록 보기, 새 장터 시작
- 완주 후 반복 진입 시 감사·개발 중 스크롤, 기록 유지 또는 즉시 재시작
- 영업 도중 새로고침에도 중복 정산되지 않는 저장 복구
- PC 및 모바일 390×844 화면, 키보드 조작, 동작 감소 대응
- 이전 Phaser 마을 소스·의존성 제거, Vite 진입점 교체

이는 기본 게임 루프의 구현 완료를 뜻합니다. 실제 재미, 경제 이해의 전이, 장기 숙련은 아직 사용자 관찰로 검증하지 않았습니다.

## 다음 순서: 실제 플레이 관찰

대상 사용자가 사전 설명 없이 한 판을 하도록 합니다. 개발자가 답을 유도하지 않고 다음을 기록합니다.

1. 첫 준비와 영업을 스스로 시작하는지, 어느 정보를 놓치는지 봅니다.
2. 손님이 돌아간 이유와 남은 돈의 변화를 자기 말로 설명하는지 봅니다.
3. 결과를 보고 자발적으로 가격·수량을 바꾸거나 같은 날을 다시 하는지 봅니다.
4. 조건이 다른 가상의 가게에서도 매출과 이익을 구분하는지 봅니다.
5. 중단 지점, 실제 세션 시간, 반복해서 하고 싶은 이유를 기록합니다.

조작 실패는 화면과 문구를 고칩니다. 판단이 단조롭다는 반응이면 경제 용어·날짜·메뉴를 늘리기 전에 선택 구조를 고칩니다. 자동 테스트 통과를 이 단계의 대체물로 삼지 않습니다.

## 첫 숙련 확장 — 보관과 내일의 준비

**보관에 쓸지, 오늘 더 준비할지**의 선택을 구현했습니다. 셋째·넷째 날 하루 600원에 최대 4잔을 다음 영업까지 보관합니다. 재료값 인상 전 4잔을 미리 준비하는 경로는 두 영업을 합쳐 200원을 아끼지만, 보관할 음료가 없으면 대여료 600원만 더 씁니다. 이 수치는 규칙 검증 결과이며 사용자 재미의 증거는 아닙니다.

첫 두 날은 기존의 수량·가격 선택을 유지합니다. 물량, 대여료, 현금, 보관분의 판매 기한을 함께 검증했고, 기존 저장 기록도 이어 읽습니다.

## 후속 제작 순서

[첫 장터 이후의 설계](design/after-first-market.md)에 진입 흐름, 단계별 선택과 완료 기준을 정리했습니다. 감사 스크롤은 구현했고, 아래 세 단계는 후속 설계입니다.

1. 달라지는 장터: 다른 손님 구성과 재료비 시점에서 같은 조작으로 판단합니다.
2. 눈에 보이는 가게 성장: 준비금 목표가 실제 간판·진열·설비 선택으로 이어집니다.
3. 여러 영업을 보는 판단: 단체 주문의 약속과 일반 손님을 받을 여유를 비교합니다.

## 다음 숙련 확장 후보

손님 조건이 달라지는 재플레이를 검토합니다. 결과를 좌우하는 단서를 준비 전에 제공하고, 정해진 손님 순서를 암기하는 숙련에서 조건을 읽는 숙련으로 옮깁니다.

장기적으로 다른 상품·공급처·고정비·신용을 검토할 수 있지만 동시에 추가하지 않습니다. 하나가 들어올 때마다 전략이 실제로 달라지는지, 초반 조작은 여전히 쉬운지 검증합니다.

## 현재 범위에 없는 것

로그인, 서버 저장, 결제, 경쟁 랭킹, 투자 시세, 대출 시스템, 티어 퀴즈, 마을 이동, 실제 가게 건축은 없습니다. 단순한 수익 배수 업그레이드나 문항 수 증가를 다음 작업의 기본값으로 삼지 않습니다.
