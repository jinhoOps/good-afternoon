# Good Afternoon. 개발 로드맵

갱신일: 2026-09-10. 현재 목표는 [초기버전 완성 계획](design/initial-release.md)의 게임 루프를 연결하고 공개 배포를 검증하는 것입니다.

## 구현된 초기버전

- 동네 장터의 다섯 오후: 첫날 수량만 고르기 → 가격 → 보관 → 최종 기록
- 공원 산책·공연 주간: 다른 수요와 비용을 읽기, 고정된 조건으로 재시도
- 가게 목표 보상: 간판·진열 공간, 첫 달성 기록, 다음 장터에도 남는 성장
- 설비 자리 하나: 넓은 보관 또는 따뜻한 레몬티, 장터별 유불리
- 내일의 단체 주문: 선불 현금과 납품 매출 분리, 재료비 확보와 진열 용량 배분
- 감사·개발 중 스크롤: 기록 보존, 같은 장터 재도전, 다음 장터·설비 선택
- 자동 저장, v1~v3 금액 이전, 최고 기록 재계산, 영업 도중 새로고침·연타 보호
- PC·모바일·키보드·동작 감소 지원

현재 규칙은 [첫 장터](design/weekend-market.md)와 [후속 장터](design/after-first-market.md)에 있습니다. 초기버전 구현과 장기 숙련·학습 효과의 입증은 구분합니다.

## 출시 점검

관련 테스트, 빌드, 브라우저 전체 흐름, 화면 캡처와 문서 일치를 확인합니다. main 푸시 후 GitHub Pages 작업 성공과 공개 주소에서 같은 루프가 실행되는지 확인합니다. 완료 근거는 [초기버전 검증 기록](validation/initial-release.md)에 기록합니다.

## 후속 단계: 테스터 모집과 실제 플레이 관찰

2026-09-10 사용자 결정으로 재미 검증은 테스터를 모아 천천히 진행합니다. 초기버전 배포를 막는 조건으로 두지 않습니다. 이번 피드백의 화면 색감·서체와 음료 기본가 3,000원 조정을 먼저 반영합니다.

대상 사용자가 사전 설명 없이 플레이하도록 합니다. 개발자가 답을 유도하지 않고 다음을 기록합니다.

1. 첫 준비와 영업을 스스로 시작하는지, 어느 정보를 놓치는지 봅니다.
2. 돌아간 손님과 현금 변화를 자기 말로 설명하는지 봅니다.
3. 결과를 보고 자발적으로 가격·수량을 바꾸거나 재시도하는지 봅니다.
4. 공원 소식이 설비 선택을 바꾸는지, 선불금과 이익을 구분하는지 봅니다.
5. 중단 지점, 실제 세션 시간, 다시 하고 싶은 이유를 기록합니다.
6. 다른 가게 상황에서도 매출과 이익을 구분하는지 확인합니다.

조작 실패는 화면과 문구를 고칩니다. 단조롭다는 반응이면 날짜·용어·메뉴를 늘리기 전에 선택 구조를 고칩니다. 자동 검증을 사용자 관찰의 대체물로 삼지 않습니다. 현재 실사용자 재미·학습 관찰 결과는 확보하지 않았습니다.

## 이후 후보

조건의 변형을 더 늘리는 일, 장기 고정비, 다른 공급처 등을 실제 플레이 결과를 보고 검토합니다. 금융 용어를 추가하는 것이 목적이 아니며 대출이 항상 손해라고 일반화하지 않습니다.

로그인, 서버 저장, 결제, 랭킹, 투자 시세, 대출, 티어 퀴즈, 마을 이동, 실제 건축은 현재 범위에 없습니다. [과거 서비스 구조](archive/2026-09-09-before-market-context.md)와 [이전 마스터리](archive/2026-09-10-mastery-spec.md)는 참고 기록입니다.
